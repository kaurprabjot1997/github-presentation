What each tool does

plain language ~4 min

What is GitHub?

  • GitHub is a shared platform for storing, reviewing, and tracking changes to code and logic.
  • It helps the team keep a single version of the truth for transformations, scripts, and reporting logic.
  • It records who changed something, when it changed, and why it was reviewed before moving to production.

What is JupyterHub?

  • JupyterHub is a shared notebook environment used for exploring data and testing analysis.
  • It is useful when analysts and data engineers need to explore data, validate assumptions, and iterate quickly.
  • It is often the starting point before logic is turned into a formal, reviewable workflow.

When do we use Python and PySpark?

  • Python is used for scripting, data preparation, automation, and ETL logic.
  • PySpark is used when we need to process larger datasets or run distributed transformations efficiently.
  • These tools help convert raw data into portfolio metrics, quality checks, and reusable transformation logic.

What is Airflow?

  • Airflow is used to schedule and orchestrate jobs in a controlled and repeatable way.
  • It is useful when tasks must run on a schedule, depend on each other, or need to move through staging and production safely.
  • It helps move analytical work from manual execution into operational execution.

What is Tableau used for?

  • Tableau is used for reporting, dashboards, and business-facing data visibility.
  • It turns validated data and portfolio logic into charts and views for decision support.
  • It is the layer where finished analysis becomes business consumption, while GitHub governs the underlying logic.

Why GitHub is relevant for the team

visibility • consistency • control ~5 min

Current context

  • Within our team, some colleagues are already using GitHub while others are still onboarding.
  • Logic and definitions can sit in individual queries, notebooks, and dashboards without a common governance layer.
  • It is not always clear who changed a metric, filter, or portfolio definition.
  • Different functions can produce slightly different interpretations of the same portfolio view unless the workflow is aligned.

What GitHub adds

  • A shared location for ETL, transformation, and reporting logic.
  • A structured review process before updates move into staging or production.
  • A clear history of changes for audit, accountability, and continuity.
  • A practical way to share knowledge and standards across our internal team during onboarding and day-to-day work.

Branching strategy

master • staging • feature work ~3 min
master
  • Production branch.
  • Connected to production Airflow jobs.
  • Protected and only updated through approved pull requests.
staging
  • Pre-production validation branch.
  • Connected to staging Airflow environment.
  • Used to test logic before release into production.
feature branch
  • Short-lived project-based branches.
  • Examples: portfolio-risk-refresh, covenant-data-fix.
  • Used for isolated work and review before moving to staging.

A key governance principle is that production code is not associated with an individual developer. Work is organized by project and business domain, which supports better traceability and shared accountability across the team.
